# 下一轮功能规格（草案）

日期：2026-10-30。四个功能：批次与交付包、客户审阅链接、模板库（一键同款完整版）、爆款视频复刻。每个功能写清楚对象、状态、接口、界面、钱、验收和不做什么，确认后即可开发。

---

## F1 批次与交付包

**目的**：一套图（以后包括视频）在系统里是一个整体，交付台按「套」核对和导出。

**对象**
- 批次 Batch = 现有 `conversations` 一行（`conversationId` 即 batchId，不新增表）。新增 `conversations.kind='batch'`、`package_key`、`product_id`、`status`。
- 输出项 = 现有套图计划行；每行提交时把 `conversationId` 写进任务（`tasks.conversation_id` 已存在）。
- 交付包模板 `delivery_packages`：key、名称、渠道、行列表（用途、比例、清晰度、提示词模板、张数）、状态。后台可编辑，客户端读取。

**批次状态（由输出项汇总，不单独存）**

| 条件 | 显示 |
|---|---|
| 有任务排队/生成中 | 生成中 |
| 全部完成，有待核对 | 待核对 |
| 有「需修改」 | 返修中 |
| 全部通过 | 可交付 |
| 已导出 | 已交付（记录导出时间） |

**接口**
- `POST /api/batches`（productId、packageKey）→ batchId
- `GET /api/batches`、`GET /api/batches/{id}`（含任务与输出）
- `GET /api/delivery-packages`；后台 `PUT /api/admin/delivery-packages/{key}`

**界面**：首页「选交付包」→ 计划表（已有 OutputPlan）→ 生成；交付台第一层按批次卡片展示，点进去才是逐张核对。

**钱**：每行独立报价、独立扣费（现状不变）；批次只汇总显示总价。

**验收**：3 张套图提交后交付台只出现 1 个批次；单张失败可单独重试且不影响其他行；整套导出 ZIP 只含当前通过版本。

**不做**：跨商品的大批量（属于批量 SKU，后续）。

## F2 客户审阅链接

**目的**：代运营把一个批次发给品牌方确认，不再微信来回传图。

**对象** `review_links`：id、batch_id、token（随机 32 字节）、过期时间、创建人、状态（active/revoked）。`review_decisions`：link_id、output 版本 id、决定（approved/changes）、批注、时间、审阅人称呼。

**流程**：交付台 → 批次 →「生成审阅链接」（有效期 7 天）→ 复制链接 → 客户网页打开，逐张通过或写批注 → 客户端交付台对应版本状态更新为「客户通过 / 客户要求修改」。

**接口**
- `POST /api/batches/{id}/review-links`、`DELETE /api/review-links/{id}`
- 公开：`GET /r/{token}`（静态审阅页，由 admin nginx 托管）、`GET /api/review/{token}`、`POST /api/review/{token}/decisions`

**安全**：token 不可猜；只读该批次的通过/待审版本图片；过期或撤销即 404；不暴露用户邮箱和价格。

**验收**：手机浏览器打开链接能看图、能提交；撤销后链接失效；客户端 1 分钟内看到客户的决定。

**前置**：F1；核对改为版本级（`Works.tsx` / `Delivery.tsx` 的 reviewStatus 迁到版本上）。

## F3 模板库（一键同款完整版）

今晚已上线最小版：灵感示例带模型/比例/清晰度/张数，点「做同款」带入首页，记录使用次数。

**下一步**
1. 统一「灵感示例」和 `apps`（已有 inputSchema、examples、modelHint、credits）为一个「模板」入口；客户端侧栏「模板」一个页面，按品类/场景筛选和搜索。
2. 提示词变量：模板提示词可写 `{商品名}` `{卖点}` `{场景}`，做同款时用选中商品自动替换（后端 `recipes.Render` 已支持渲染）。
3. 沉淀通道：后台任务详情「设为模板」（复制提示词、参数、成品图，去掉用户信息，默认草稿）；客户端作品「存为我的模板」（仅自己可见）。
4. 排序：后台按使用次数、生成成功率排序；成功率 = 使用该模板生成的任务成功数 / 总数（任务记录 `template_id`）。

**验收**：选一个商品后点做同款，提示词中的变量被商品信息替换；后台能把一条成功任务一键转为草稿模板并发布。

## F4 爆款视频复刻

**目的**：上传一条参考爆款视频，拆出结构，换成自己的商品重新生成。

**前置**：视频 V0（图生视频单镜头）和 V1（本机合成）验收通过；确认一个可用的视频理解模型渠道（通义 / 豆包视觉）。

**流程与状态**

```
上传参考视频 → 拆解中 → 待确认结构 → 生成首帧 → 逐镜生成 → 合成 → 待核对 → 已交付
                                  ↘ 任一镜头失败：只重做该镜头
```

**拆解输出（JSON，可编辑）**：总时长、开头钩子类型、节奏；镜头列表（序号、时长、景别、运镜、画面描述、字幕、口播、转场）；配乐风格。

**换商品**：每个镜头首帧用商品依据图 + 画面描述生成图片（图片模型）；字幕和口播用商品事实重写，禁用声明过滤。

**接口**
- `POST /api/video-remakes`（上传的参考视频资产 id、商品 id）→ 拆解任务
- `GET /api/video-remakes/{id}`；`PUT /api/video-remakes/{id}/structure`
- `POST /api/video-remakes/{id}/shots/{n}/generate`
- 合成在客户端本机（Tauri 内置 ffmpeg）

**钱**：拆解按次计价；每个镜头首帧和视频分别报价；开始前展示整条预算，超出上限需确认。

**合规**：只复刻结构与节奏，不复用原画面、音乐、人物；上传时用户勾选「我有权使用该视频作参考」；成片加 AI 生成标识。

**验收**：一条 15 秒参考视频 → 结构 4–6 镜可编辑 → 换成真实 SKU 后出 9:16 成片，商品外观与依据图一致，总成本在预算内。

**不做（首版）**：从 TikTok 链接直接抓取视频、数字人口播、自动发布。
